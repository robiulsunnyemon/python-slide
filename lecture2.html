Mental Model

Variables in Python: Tags, Not Boxes!

In Python, variables do not store values directly; they act as reference tags (pointers) pointing to objects in memory.

RAM / Heap Memory Reference Map:
score
points to
100
Address: 0x7fff4a20
int
user_name
points to
"Robiul"
Address: 0x7fff9b10
str

Key Variable Rules in Python:

  • No Declaration Keyword: No var, let, or int needed. Assignment creates the binding.
  • Valid Names: Can contain letters, digits, and underscores (_), but cannot start with a digit.
  • Naming Convention: PEP 8 mandates snake_case for variables (e.g., total_price).
Data Types

The 5 Core Primitive Data Types

Python has built-in primitive types to represent numbers, text, logic, and absence of value:

int

Whole Numbers

Unlimited precision (no integer overflow in Python 3).

float

Decimals

64-bit IEEE 754 floating-point representation.

str

Text Sequence

Boolean Truth

Capital True & False (subclass of int).

NoneType

Null / Absence

Represents empty state or void function return.

Type System

Python is Dynamically AND Strongly Typed

Understanding this distinction is one of the most common technical interview questions:

1. Dynamically Typed

Variable types are determined automatically at runtime. A variable can point to an integer first, and then to a string later without error:

data = 42         # data is int
print(type(data))  # <class 'int'>

data = "Python"   # Re-assigned to str
print(type(data))  # <class 'str'>

2. Strongly Typed

Python never implicitly converts conflicting data types behind your back (unlike JavaScript or PHP):

num = 10
text = "20"

# In JavaScript: 10 + "20" -> "1020"
# In Python: Raises TypeError!
result = num + text  # ❌ TypeError
result = num + int(text) # ✅ 30
Memory Deep Dive

Memory Allocation, id() & Small Integer Caching

Inspect the exact memory address of any object with Python's built-in id() function:

memory_demo.py
a = 250
b = 250

print(id(a))  # e.g., 14072384920
print(id(b))  # Identical address!
print(a is b)  # True (points to same object)

x = 1000
y = 1000
print(x is y)  # False in interactive shell

🧠 CPython Optimization: Small Integer Cache

To save memory and optimize execution speed, CPython pre-allocates an array of all integers between -5 and 256 at interpreter startup.

💡 Key Takeaway:

Always use == when comparing values (equality). Only use is when comparing object identity (e.g., val is None).

Type Casting

Type Casting: Implicit vs Explicit

Converting data from one type to another is essential when processing input and calculations:

🔄 1. Implicit Conversion (Automatic)

Python automatically converts smaller data types to wider types to prevent data loss:

x = 10       # int
y = 2.5      # float
z = x + y    # 12.5 -> automatically float!
print(type(z)) # <class 'float'>

🛠️ 2. Explicit Conversion (Manual)

Using conversion functions (int(), float(), str(), bool()):

age_str = "25"
age_num = int(age_str)     # 25 (int)
price = float("99.9")      # 99.9 (float)
status = bool(1)           # True
empty_check = bool("")     # False (falsy)
⚠️ Watch Out: int("3.14") will raise a ValueError! Convert through float first: int(float("3.14")) → 3.

User Input & Output

User Input with input() & Modern f-strings

Capturing user keyboard interaction and formatting professional console messages:

user_profile.py
# input() ALWAYS returns a string (str)!
user_name = input("Enter your name: ")
birth_year = int(input("Enter birth year: "))

current_year = 2026
calculated_age = current_year - birth_year

# Modern Python f-string (PEP 498)
print(f"Hello {user_name}! In {current_year}, you will be {calculated_age} years old.")

⭐ Golden Rule of input():

Everything captured by input() is treated as text (str). If you expect numerical input for math calculations, you must wrap it with int() or float().

Why f-strings are Superior:

f-strings (f"...") evaluate expressions directly inside curly braces { } cleanly without messy commas or manual str() concatenation.

Pitfalls

4 Common Data Type Gotchas & Bugs ⚠️

Avoid these frequent beginner mistakes when handling Python variables and calculations:

❌ 1. String Concatenation Trap

a = input() # User enters 5
b = input() # User enters 10
print(a + b) # → "510" (NOT 15!)

Always cast to int() before arithmetic on inputs.

❌ 2. Floating-Point Precision

print(0.1 + 0.2 == 0.3) # → False!
print(0.1 + 0.2) # → 0.30000000000000004

Floating-point binary math creates rounding nuances. Use round() or math.isclose() for comparison.

❌ 3. TypeError on Mismatched Print

score = 95
print("Score is: " + score) # → TypeError!

Fix: Use f-strings print(f"Score is: {score}") or str(score).

❌ 4. Division Operator Confusion

10 / 2 → 5.0 (always float)
10 // 2 → 5 (integer floor division)

Remember that single slash / always produces a float in Python 3.
