Disk Persistence

Context Managers: The with open() Statement

Never use manual file.close()! The with statement guarantees automatic resource cleanup even if exceptions occur:

file_manager.py
# 1. Writing to a file ('w' creates/overwrites)
with open("server.log", "w", encoding="utf-8") as f:
    f.write("[INFO] Server initialized successfully.\n")
    f.write("[INFO] Port 8000 listening.\n")

# 2. Appending data ('a' preserves existing lines)
with open("server.log", "a", encoding="utf-8") as f:
    f.write("[AUTH] User Robiul logged in.\n")

# 3. Line-by-line memory-efficient streaming
with open("server.log", "r", encoding="utf-8") as f:
    for line in f:
        print(line.strip())

Core File Opening Modes:

  • 'r': Read (Default, error if file missing)
  • 'w': Write (Truncates/wipes existing content!)
  • 'a': Append (Adds to end of file safely)
  • 'b': Binary mode (e.g. 'rb' for images/PDFs)
Mandatory Best Practice: Always include encoding="utf-8" to prevent cross-platform text corruption on Windows!
Structured Storage

Working with JSON (JavaScript Object Notation)

The universal format for REST APIs and configuration files powered by Python's built-in json module:

json_persistence.py
import json

config = {
    "app_name": "AI Assistant",
    "version": 2.5,
    "features": ["vision", "voice"],
    "active": True
}

# 1. Dumping Python dict to a JSON file
with open("config.json", "w") as f:
    json.dump(config, f, indent=4)

# 2. Loading JSON file back into Python dict
with open("config.json", "r") as f:
    loaded_data = json.load(f)

print(loaded_data["app_name"])  # "AI Assistant"

Memory Cheat Sheet: s stands for String!

  • json.dump(obj, file): Serializes object to disk File.
  • json.dumps(obj): Serializes object to a Python String.
  • json.load(file): Deserializes directly from disk File.
  • json.loads(string): Deserializes from a raw JSON String.
Crash-Proof Code

Exception Handling: try / except / else / finally

Intercept runtime errors gracefully so your system never crashes in production:

robust_parser.py
def safe_division(a, b):
    try:
        result = a / b
    except ZeroDivisionError:
        print("❌ Error: Cannot divide by zero!")
        return None
    except TypeError as e:
        print(f"❌ Error: Invalid type - {e}")
        return None
    else:
        # Runs ONLY if NO exceptions occurred!
        print("✅ Calculation succeeded.")
        return result
    finally:
        # ALWAYS runs no matter what!
        print("🔒 Cleanup / Telemetry logged.")

The 4 Stages of the Lifecycle:

try

Risky code

except

Handles error

else

If success

finally

Always runs
⚠️ Golden Rule: Never write bare except:! Always catch specific exceptions (e.g. except ValueError:).
Custom Architecture

Raising & Defining Custom Exceptions

Create meaningful, domain-specific error types for enterprise business logic:

bank_exceptions.py
# 1. Custom Exception Class
class InsufficientFundsError(Exception):
    """Raised when account balance is lower than withdrawal."""
    pass

# 2. Triggering with raise
def withdraw(balance: float, amount: float) -> float:
    if amount > balance:
        raise InsufficientFundsError(f"Cannot withdraw ${amount}; balance is ${balance}.")
    return balance - amount

try:
    withdraw(100, 500)
except InsufficientFundsError as err:
    print(f"Caught custom error: {err}")

Why Custom Exceptions Matter:

Instead of generic ValueError or returning error strings like "error", custom exceptions enable specific catch blocks in large frameworks (FastAPI / Django) to trigger HTTP 400 or 402 payment errors automatically!

Pitfalls

4 Common File I/O & Exception Traps ⚠️

Avoid these high-risk errors in file systems and exception handling:

❌ 1. Overwriting with 'w' Mode

open("data.txt", "w") # Wipes all existing data!
Fix: Use "a" mode for appending.

❌ 2. Bare except: Anti-Pattern

except: pass # Catches Ctrl+C / SystemExit!
Fix: except Exception: (or specific errors).

❌ 3. Missing UTF-8 Encoding

open("file.txt", "r") # Crashes on emojis in Windows!
Fix: Always open(..., encoding="utf-8")

❌ 4. Not Closing Files (No with)

f = open(...) # Locks file / resource leak!
Fix: Always with open(...) as f:

Mini-Project: Crash-Proof JSON Database

A robust CRUD database layer persisting user profiles with automatic file creation and backup:

json_db.py
import json

def save_user(user_id: str, name: str, db_path="users.json"):
    try:
        with open(db_path, "r") as f:
            db = json.load(f)
    except (FileNotFoundError, json.JSONDecodeError):
        db = {}  # Initialize fresh DB if missing

    db[user_id] = {"name": name, "created_at": "2026-08-17"}

    with open(db_path, "w") as f:
        json.dump(db, f, indent=2)
    
    print(f"✅ User {name} saved successfully!")

save_user("usr_1", "Robiul Suny")

Key Engineering Design:

Notice how save_user() anticipates two separate failure modes simultaneously: FileNotFoundError (first time running) and JSONDecodeError (corrupted empty file). Both gracefully fall back to an empty dict {} without crashing the app!
