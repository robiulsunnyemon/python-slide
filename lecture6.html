Key-Value Mappings

Python Dictionaries: Instant $O(1)$ Lookup

A dictionary stores data as associative {key: value} pairs powered by an internal Hash Table:

Hash Table Mappings:
"name" → hash() → "Robiul"
"role" → hash() → "AI Engineer"
"experience" → hash() → 5

3 Core Dictionary Rules:

  • 1. Keys Must Be Immutable (Hashable): Strings, numbers, and tuples are valid keys. Lists and dicts are NOT!
  • 2. Keys Are Unique: Assigning to an existing key overwrites its previous value.
  • 3. Preserves Insertion Order: Guaranteed since Python 3.7.
Defensive Access

Defensive Access: .get() & Iteration

Direct bracket access dict["key"] crashes with KeyError if missing; use .get() for safety:

dict_safety.py
user = {"username": "robiul", "is_vip": True}

# ❌ Risky: user["email"] -> KeyError!

# ✅ Safe Defensive Access with default fallback
email = user.get("email", "not_provided@domain.com")
print(email)  # not_provided@domain.com

# Traversing Keys and Values
for key, value in user.items():
    print(f"{key} → {value}")

🧰 Vital Dictionary Methods:

  • .keys() • .values() • .items()
  • .pop(key, default): Removes key and returns value
  • .setdefault(key, default): Inserts only if absent
Python 3.9+ Merge Operator (|):
merged = dict_a | dict_b → Clean modern union!
Unique Collections

Python Sets: Unordered & Guaranteed Unique

A set is an unordered collection that automatically deduplicates all entries:

set_demo.py
# Instant Deduplication
raw_ids = [101, 102, 101, 103, 102, 104]
unique_ids = set(raw_ids)
print(unique_ids)  # {101, 102, 103, 104}

# Fast O(1) Membership Testing
print(103 in unique_ids)  # True (Instant lookup!)

# ⚠️ Empty Set Creation Gotcha:
empty_dict = {}     # dict, NOT set!
empty_set = set()   # Correct empty set

Why Sets are Lightning Fast:

Checking item in my_list requires scanning every element ($O(N)$ linear time). Checking item in my_set computes the hash in $O(1)$ constant time, whether you have 10 or 10,000,000 items!

🔒 frozenset: An immutable version of a set that can be used as a dictionary key.
Set Theory

Mathematical Set Operations

Venn diagram operations built natively into Python's syntax:

1. Union (|) & Intersection (&)

frontend = {"HTML", "CSS", "JS", "Python"}
backend = {"Python", "SQL", "FastAPI"}

# All unique skills (Union)
all_skills = frontend | backend

# Shared common skills (Intersection)
common = frontend & backend  # {'Python'}

2. Difference (-) & Symmetric Diff (^)

# Frontend only (Difference)
fe_only = frontend - backend  # {'HTML', 'CSS', 'JS'}

# In either, but NOT both (Symmetric Diff)
unique_to_one = frontend ^ backend
Pythonic Elegance

Dictionary & Set Comprehensions

Transform and filter key-value pairs and sets with elegant one-line expressions:

📖 Dictionary Comprehension

prices_usd = {"laptop": 1000, "mouse": 25, "gpu": 600}
bdt_rate = 120

# {k: v for k, v in dict.items() if condition}
prices_bdt = {item: price * bdt_rate for item, price in prices_usd.items() if price > 50}
# {'laptop': 120000, 'gpu': 72000}

🎯 Set Comprehension

names = ["robiul", "emon", "robiul", "tanvir"]

# Clean, deduplicate and capitalize
clean_names = {name.title() for name in names}
# {'Robiul', 'Emon', 'Tanvir'}

Mini-Project: Blog Tag & Social Analytics

Extract unique tags across articles and compute readership intersection stats:

tag_analytics.py
post1_tags = {"python", "ai", "backend", "data"}
post2_tags = {"fastapi", "python", "docker", "backend"}

# Analytics using Set Theory
all_tags = post1_tags | post2_tags
overlap = post1_tags & post2_tags
unique_p1 = post1_tags - post2_tags

print(f"Total Unique Tags ({len(all_tags)}): {all_tags}")
print(f"Common Bridge Tags: {overlap}")
print(f"Exclusive to Post 1: {unique_p1}")

Real-World Applications:

Recommendation engines (Netflix / Spotify / Facebook) use set intersection (Jaccard Similarity) to recommend movies, songs, and mutual friends based on overlapping user taste sets!

🚀 $O(1)$ set arithmetic makes recommendation calculations fast at scale.
Pitfalls

4 Common Dict & Set Gotchas ⚠️

Avoid these frequent data structure traps in technical assessments:

❌ 1. Direct Bracket KeyError

d = {"a": 1}
print(d["b"]) # KeyError: 'b'
Fix: d.get("b", default_value)

❌ 2. Unhashable Key Type

d = {[1, 2]: "coords"} # TypeError: unhashable 'list'
Fix: Use tuple: d = {(1, 2): "coords"}

❌ 3. Empty Set Syntax Trap

s = {} # Creates empty dict, not set!
Fix: s = set()

❌ 4. Mutating Dict in Loop

for k in d: del d[k] # RuntimeError!
Fix: Iterate over list(d.keys()):
