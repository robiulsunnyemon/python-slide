Internals

Behind The Scenes: How Python Works

What happens internally when you execute python app.py in the terminal:

Step 01

Source Code (.py)

Human-readable Python instructions written by the developer

Step 02

CPython Compiler

Validates syntax & compiles source code into Bytecode

Step 03

Bytecode (.pyc)

Platform-independent intermediate representation

Step 04

PVM (Virtual Machine)

Interprets bytecode into machine code executed by the CPU

💡 Interview Insight: While Python is commonly classified as an "Interpreted Language", it undergoes compilation to bytecode first, followed by line-by-line interpretation via the Python Virtual Machine (PVM).

Comparison

Compiled vs. Interpreted Languages

Understanding the execution lifecycle and developer trade-offs:

Feature Compiled (e.g., C / C++ / Rust) Interpreted (e.g., Python / JavaScript)
Execution Model Entire codebase translates to machine code (.exe) Bytecode interpreted line-by-line during runtime
Development Speed Requires re-compilation after every modification Rapid Prototyping & Testing
Portability Platform-dependent binary binaries must be built Write Once, Run Anywhere (PVM)
Debugging Experience Errors listed after the full compilation pass Stops and pinpoints the exact line upon exception

Best Practices

Comments & Clean Code Rules (PEP 8)

Professional engineers write code optimized for human readability first.

pep8_rules.py
# 1. Single-line comment
student_count = 45  # Total active students

"""
2. Multi-line docstring
Used to document functions, classes,
and complex algorithmic modules.
"""

# 3. PEP 8 Naming Standard: snake_case
user_full_name = "Robiul Emon"  # Recommended
# userFullName = "..."         # Non-Pythonic

💡 Golden Rules of PEP 8:

1. 4-Spaces Indentation: Never mix tabs and spaces; consistently use 4 spaces per indentation level.
2. snake_case: Format variables and function names in lowercase separated by underscores (e.g., calculate_total).
3. Readable Spacing: Keep single spaces around operators (e.g., x = 5 + 2 instead of x=5+2).
Common Pitfalls

5 Common Beginner Pitfalls & Errors ⚠️

Recognizing these frequent stumbling blocks will accelerate your debugging workflow:

❌ Case Sensitivity Mistake

Print("Hello")  ➔  NameError: name 'Print' is not defined

Python is strictly case-sensitive. Built-in keywords like print must be lowercase.

❌ IndentationError

  print("Hello")  ➔  IndentationError: unexpected indent

Leading whitespace is semantically meaningful. Do not indent top-level statements arbitrarily.

❌ Unclosed Quotes & Parentheses

print("Hello)  ➔  SyntaxError: unterminated string literal

Every opened string quotation and function parenthesis must have a matching closing pair.

❌ Wrong Directory / File Name

python test.py  ➔  FileNotFoundError

Ensure your terminal's current working directory (pwd / cd) matches the script location.
