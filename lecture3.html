Concept

Control Flow: How Code Makes Choices

By default, Python executes code line-by-line from top to bottom. Conditionals introduce intelligent decision forks:

Logical Decision Flow:
Decision Node
is_logged_in == True?
True Branch
Show Dashboard
False Branch
Redirect Login

🔑 The 3 Rules of Python Conditionals:

  • Colon (:) is Mandatory: Every conditional header statement must terminate with a colon.
  • Indentation Defines Blocks: Statements indented 4 spaces belong strictly inside that branch.
  • Boolean Conversion: Python evaluates the expression's truth value (bool(expr)).
Syntax

The if-elif-else Decision Ladder

Handle multiple mutually exclusive conditions with clean sequential evaluation:

grade_system.py
score = 85

if score >= 90:
    grade = "A+ (Outstanding)"
elif score >= 80:
    grade = "A (Excellent)"
elif score >= 70:
    grade = "B (Good)"
elif score >= 50:
    grade = "C (Pass)"
else:
    grade = "F (Retake Required)"

print(f"Final Result: {grade}")

⚡ Execution Rules:

1. Python evaluates conditions from top to bottom.

2. As soon as ONE condition evaluates to True, its block executes and the entire rest of the ladder is skipped!

3. else is optional and acts as the fallback safety net if no condition matched.

💡 Pro-Tip: Multiple independent if statements will ALL be evaluated; an if-elif ladder is mutually exclusive!
Performance & Safety

Short-Circuit Evaluation with and / or

Python evaluates logical expressions lazily for maximum performance and defensive safety:

1. and Short-Circuit

If the first condition is False, Python stops immediately because the whole expression cannot be True:

# If user is None, user.name is NEVER accessed!
# Prevents AttributeError / crash:
if user is not None and user.is_active:
    print("Welcome active user!")

2. or Short-Circuit

If the first condition is True, Python stops immediately because the whole expression is already True:

is_admin = True
# check_database_permission() is NOT called!
if is_admin or check_database_permission():
    print("Access Granted!")
Chained Comparisons in Python: You can write 18 <= age <= 65 directly instead of age >= 18 and age <= 65!
Architecture

Nested Conditionals & The pass Keyword

How to handle multi-tiered logic cleanly and utilize Python's null-statement placeholder:

loan_eligibility.py
age = 24
monthly_income = 45000
has_good_credit = True

# Clean Nested Decision
if age >= 21:
    if monthly_income >= 30000 and has_good_credit:
        print("✅ Loan Approved!")
    else:
        print("❌ Rejected: Income/Credit below threshold.")
else:
    print("❌ Rejected: Must be at least 21 years old.")

🚫 Avoid "Arrow Anti-Pattern":

The Zen of Python states: "Flat is better than nested." Avoid nesting more than 2-3 levels deep; use guard clauses and compound and conditions.

The pass Keyword:

In Python, an empty block causes an IndentationError. pass is a placeholder that does nothing:

if in_development:
    pass # TODO: Implement later
Pythonic Syntax

The Ternary Operator (Inline if-else)

Write elegant, concise one-line conditionals for assignments and return values:

❌ Verbose Standard Way (4 lines):

age = 20

if age >= 18:
    status = "Adult"
else:
    status = "Minor"

✅ Pythonic Ternary (1 clean line):

age = 20

# value_if_true IF condition ELSE value_if_false
status = "Adult" if age >= 18 else "Minor"

print(f"Access: {status}")  # Access: Adult

Real-World Practical Usage:

discount = 0.20 if is_vip_member else 0.05 • label = "items" if count > 1 else "item"

Python 3.10+ Feature

Modern Pattern Matching: match-case

Introduced in PEP 634, match-case is much more powerful than classic switch-case statements in other languages:

http_router.py
status_code = 404

match status_code:
    case 200:
        print("OK: Request Succeeded")
    case 301 | 302:
        print("Redirect: Resource Moved")
    case 400 | 404:
        print("Client Error: Bad Request / Not Found")
    case 500:
        print("Server Error: Internal Failure")
    case _:
        print("Unknown Status Code")

Key Pattern Matching Superpowers:

  • 1. Pipe Symbol (|): Match multiple alternative patterns in a single case.
  • 2. Wildcard (_): Acts as the default fallback matching anything (like else).
  • 3. Pattern Guards: Add conditions with case x if x > 100:.

Real World Project

Mini-Project: Smart ATM Cash Dispenser

A production-style decision matrix validating authentication, balance, and limits:

atm_system.py
correct_pin = "1234"
account_balance = 5000
daily_limit = 2000

entered_pin = "1234"
withdraw_amount = 1500

if entered_pin != correct_pin:
    print("❌ Invalid PIN. Card locked.")
elif withdraw_amount > daily_limit:
    print(f"❌ Exceeds daily limit of ${daily_limit}.")
elif withdraw_amount > account_balance:
    print("❌ Insufficient funds in account.")
else:
    account_balance -= withdraw_amount
    print(f"✅ Success! Dispensing ${withdraw_amount}.")
    print(f"Remaining Balance: ${account_balance}")

Architectural Insights:

Notice how the logic uses Guard Clauses (Early Exits). By checking and eliminating error conditions first (Invalid PIN, Over Limit, Low Balance), the "happy path" (successful withdrawal) stays clean and readable at the end!

💡 Industry Standard: Fail fast, fail early!
Pitfalls

4 Common Control Flow Gotchas ⚠️

Avoid these four classic logic errors that trap beginner developers:

❌ 1. Assignment (=) vs Equality (==)

if x = 10:  →  SyntaxError: invalid syntax

= is for assigning variables; == is for comparison!

❌ 2. Unintended Multiple IFs

if score >= 80: print("A")
if score >= 50: print("Pass") # Both execute!

Use elif when conditions must be mutually exclusive.

❌ 3. The "Truth Value of Non-Empty" Bug

if color == "red" or "blue": # Always True!
Fix: if color == "red" or color == "blue":

"blue" by itself is a non-empty string which evaluates to True!

❌ 4. Missing Colon & Indentation Trap

if x > 5 print(x)  →  SyntaxError
Always include : and indent the next line!
